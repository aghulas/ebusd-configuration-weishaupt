# Weishaupt catalog

One row per readable point of a Weishaupt WCM system, as the single source for the ebusd definitions and for a
Home Assistant integration. Generated by `diag/build_catalog.py` from an export of the "WCM" workbook (memory maps
named after the `.SYC` symbol tables, EEPROM dumps of both burners with the parameter levels, regulator registers,
ComfortSoft info values); the generator only reorganises that material and never talks to the bus.

## Files

### `wtc-memory.csv` — WTC burner control memory (`5000` read to the slave address: bc1 `08`, bc2 `18`)

| Column | Content |
|---|---|
| `space`, `address` | `ram` (type 01), `xram` (03, page F0), `eeprom` (02; pages 0x000–0x3FF) |
| `name`, `size` | symbol name; bytes (fault counters 2, statistics counters up to 3) |
| `category`, `level` | EEPROM: `manufacturer`, `heating_specialist`, `user`, `errors`, `statistics`, `ion_calibration`; RAM/XRAM: `config`, `live`. `level` is the access level of WCM-Diagnose (`info` = read only) |
| `block_crc` | address of the CRC byte protecting the block (see below) |
| `param`, `label_fr`, `unit`, `divider`, `confidence` | WCM-Diagnose parameter (P-number) when matched; `confidence` says how |
| `read_id` | ebusd ID of the read, Weishaupt CRC included (`hex 08 5000 NN <read_id>`) |
| `ref_bc1`, `ref_bc2`, `ref_value` | values from the workbook dumps (EEPROM of both burners; one RAM/XRAM dump) |
| `notes` | annotations of the workbook |

The EEPROM parameter names (e.g. `MAXTVSOLL` at 0x01B) come from the workbook, not from the `.SYC` files, whose
"Konstanten" section names other tables; `WH11928.inc` therefore has no read for them. On 29/10/2026 36 reads of
these points on both burners returned exactly the workbook values, and WCM-Diagnose reads the heating specialist
screen as 12-byte blocks from 0x01B.

### `regulator-registers.csv` — regulators KA, EM, FS, SC (`0902` read / `0903` write, no CRC)

`name`, `comment`, `menu` (menu number of the regulator, from the comment), `register`, `bank`, `id`
(register, bank, length), `templates`, `register_inc` (`r`, `w`, `rw`: already defined in `weishaupt/register.inc`).

### `wtc-info-5022.csv` — ComfortSoft info values read with `5022`

`name`, `zz`, `pbsb`, `id` (CRC included), `factor`, `flags`, `unit`.

## EEPROM blocks protected by a check byte

| Block | Bytes | Check byte | Fault if wrong |
|---|---|---|---|
| Manufacturer | 0x002–0x017 | 0x018 `EE_CONST_CRC` | F52 |
| Heating specialist | 0x01B–0x050 | 0x051 `KES_DAT_CRC` (bc1 184, bc2 200) | F51 |
| Heating specialist, copy | 0x053–0x088 | 0x089 `EEAEPKCRC2` | |
| Manufacturer, copy | 0x08C–0x0A1 | 0x0A2 `EE_CONST_CRC` | |
| Identification (build state, customer, variant, serial number) | 0x1EE–0x1F5 | 0x1F6 `EEA_PRUEF_CRC` | |
| User (flow setpoint, setback, DHW setpoint, summer/winter) | 0x300–0x303 | 0x304 `EEA_MAINPARACRC` | |

The check byte is computed as below (WCM-Diagnose 5.5.19, "calculate CRC" button of its EEPROM window,
function 0x64D5FC; implemented as `block_check()` in `diag/build_catalog.py`). It reproduces the six blocks of both
burners exactly, with a single possible start address each:

```
value = 0
for each byte of the block: value = value * 2; if value > 0xFF: value = (value - 0x100) XOR 0x21; value = value XOR byte
check byte = 0xFF - value
```

The bytes 0x01B–0x051 and 0x002–0x018 are identical to their copies 0x053–0x089 and 0x08C–0x0A2 on both burners.
Changing a parameter therefore means writing the byte and the check byte in both copies. **Still do not write these
blocks**: how the WTC takes over a new EEPROM value (RAM working copies such as `SONDERNIVEAU` at RAM 0x0B2,
`EM_EE_REDUND` at XRAM 0xF0B8), and in which order the official tool writes, are not known yet.

## Access rules (measured on 29/10/2026)

Active reads and writes (from Home Assistant or ebusd) always use the Weishaupt CRC, calculated at runtime;
`0902`/`0903` are kept for passive listening to what the devices exchange (e.g. FS → EM settings).

| Access | Registers (regulators KA, EM, FS, SC) | Memory (WTC) |
|---|---|---|
| Passive | `0902` read `reg bank len` (up to 8 bytes = 4 consecutive registers), `0903` write `reg bank value` | — |
| Active read | `5022 [CRC] reg bank [reg bank …]`: list of up to 4 registers, 2 bytes each, no status byte | `5000 [CRC] desc [desc …]`: short `[(len-1)<<4 \| type] addr` (page 0) or long `06 page [(len-1)<<4 \| type] addr`, mixable; contiguous up to 16 bytes; answer = status `00` + bytes |
| Active write | `5023 [CRC] reg bank value [reg bank value …]`: up to 3 registers (16 data bytes) | `5001 [CRC] desc value` to the master address of the WTC (slave − 5) |

- One register written with `5023`: accepted, the regulator acknowledges in time and answers with an empty slave
  part. Several registers: accepted (values read back changed), but the regulator sends its acknowledge about 75 ms
  after the CRC (probably while storing), far beyond the eBUS timing, so ebusd reports a timeout and repeats the
  write; `--receivetimeout` (tested at 100 ms) does not help, it only covers the slave answer. **Write one register
  per `5023` telegram** (a day of a time program = 3 writes) and always read back after a write.
- The EM regulators do not check the `5023` CRC (they accept a CRC over the ID only, or `00`); the WTC rejects a
  `5000` read with a wrong CRC. Send the correct CRC anyway.
- A heating circuit is set in its FS, which pushes the values to its EM with `0903` about every 2 minutes: a value
  written directly into an EM only lasts until the next push. The room sensor correction (menu 101) is not settable
  on em1 or FS1 (probably requires a remote control unit).
- Time programs: 3 slots per day, each register = end, start in quarters of an hour (`0x18` = 06:00, `0x58` =
  22:00), `0x80 0x80` = unused slot; to be confirmed on a regulator display.

## Known limits

- P-numbers are matched by symbol name and by the value WCM-Diagnose displayed (bc1, 29/10/2026); P13–P17
  (inputs/outputs), P23, P32 and P40 are not matched yet. `NG_HZ_MIN` (P36) is ambiguous: 23 % is also the value of
  `NG_HZ_FREI` and `NG_WW_MIN`.
- The name at EEPROM 0x000 (`MAXTVSOLL`, value 255) is probably a workbook artefact.
- SFR and ROM are not listed (no names in the workbook; SFRs are I/O ports and must never be written).
- Scaling (`divider`) is only set when obvious; most raw bytes are °C, % or minutes as shown by WCM-Diagnose.
